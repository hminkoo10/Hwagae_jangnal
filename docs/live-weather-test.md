# 미국 날씨 · 미래 발주 계획 직접 테스트

## Walmart 미국 날씨 시연 — 기본 경로

1. 점주로 로그인하고 **실시간 TFT 테스트 매장 만들기**를 누릅니다.
2. **Walmart 공개 판매 · 미국 날씨**를 선택합니다. 댈러스·뉴욕·시애틀 중 날씨 지역과 Walmart 매장 4·24·17 중 판매 샘플을 고릅니다.
3. 공개 판매와 원본 관측 날씨 **112일**의 날짜를 매장 현지 오늘에 맞춰 옮긴 새 매장이 생성됩니다. 오늘 판매도 마감된 것으로 가정한 시연입니다. 기존 매장 자료는 변경하지 않습니다.
4. **7일 판매 예측**에서 다음 7일의 NOAA GFS/HRRR 예보와 `Walmart 예보 TFT · 실험` 결과를 확인합니다. 날짜와 시간대는 미국 현지 기준입니다.
5. **발주 계획**에서 **발주 예정일**을 오늘부터 6일 뒤 사이로 고르고 추천을 계산합니다. 발주 전 판매·기존 입고·만료를 먼저 계산하고, `발주 예정일 + 공급사 입고기간`에 새 상품이 도착하는 것으로 계산합니다.
6. 수량을 수정해 저장·확정하고 CSV/Excel을 내보냅니다. 파일의 판매 기준일·발주 예정일·입고예정일을 확인합니다.
7. 과거를 보려면 **7일 판매 예측**의 **판매 기준일**을 이전 날짜로 바꿉니다. 56일 판매가 있는 범위에서 과거 날씨 시나리오를 실행합니다. 현재 재고로 과거 주문을 계산하지 않으며, 과거 개인 발주 체험은 별도 **TFT 체험** 탭을 사용합니다.

필요한 예측 길이는 `발주 지연일 + 입고기간 + 발주 주기 - 1`입니다. 7일을 넘는 상품은 이유를 표시하고 계산하지 않습니다. 미래의 판매 마감일을 선택하는 대신 미래 **발주 예정일**을 선택합니다. 아직 발생하지 않은 판매를 실측 기록으로 만들지 않습니다.

### 데이터와 모델 구분

- 원본 판매·관측: Kaggle Walmart Stormy Weather, 2014-01-02~2014-04-23. `ml/build_scenario_history.py`로 검증된 원본 ZIP에서 3개 매장·10개 상품을 추출합니다.
- 미국 도시는 사용자가 선택한 **날씨 시연 위치**입니다. 원본 파일에는 매장의 실제 좌표가 없으므로 특정 Walmart 위치로 주장하지 않습니다.
- 과거 입력 날씨도 원본 관측의 날짜를 옮깁니다. 미래 입력은 선택 지역에서 현재 조회한 실제 예보입니다. 두 지역이 일치한다고 가정한 실험이며 실제 현재 매장 정확도는 검증하지 않았습니다.
- 모델은 기존 Walmart 체크포인트입니다. 새 `provided_forecast` 경로는 미래 7일 예보를 decoder에 전달합니다. 기존 persistence 방식으로 측정한 평가 지표는 이 경로의 성능이 아닙니다.
- 가격·원가(원)·재고·입고기간은 시연 가정입니다. 미국 실제 가격 자료가 아닙니다.
- 과거 날짜는 오래된 구간의 재분석, 최근 구간의 수치모델 자료와 현재 예보를 사용합니다. **그 당시 발급된 7일 예보로 평가한 결과가 아닙니다.**
- 출처·조회 시각·좌표·시간대·7일 입력값은 예측에 보존합니다. 모델 발급 시각과 조회 시각을 혼동하지 않습니다.

미국 예보: [Open-Meteo NOAA GFS/HRRR](https://open-meteo.com/en/docs/gfs-api). 과거 자료: [Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api). 단위는 API의 °C/mm/m/s를 기존 Walmart 모델의 °F/inch/mph로 변환합니다.

## 합성 자료 매장 — 기존 경로

일반 매장의 판매·재고·발주 흐름에서 **실제로 조회한 7일 예보를 TFT 입력으로 사용**합니다.
테스트 매장의 상품·가격·56일 판매·재고·입고는 가상 자료이며, 새 모델도 합성 자료로 학습한 해커톤용 TFT입니다.
기존 Walmart 과거 모델과 평가 수치는 별도로 유지합니다.

## 웹에서 시작

1. 점주 계정으로 로그인하고 **실시간 TFT 테스트 매장 만들기**를 누릅니다.
2. **합성 자료 매장**을 선택하고 매장 이름과 지역을 정합니다. 해당 좌표로 Open-Meteo 예보를 조회합니다.
3. 새 매장이 선택되면 모델 준비 상태를 확인합니다. 가상 상품 5개와 오늘 마감까지 56일 판매, 예시 재고·입고가 들어 있습니다. 기존 매장의 자료는 바뀌지 않습니다.
4. **7일 판매 예측**에서 모델 이름, 실시간 예보 사용 여부, 예보 기간·조회 시각과 상품별 수량을 확인합니다.
5. **재고 확인**에서 한 상품의 재고나 입고 예정 수량을 바꿉니다. 예시 재고는 테스트용으로 확인된 값이므로 실제 보유 재고로 설명하지 않습니다.
6. **발주 계획**에서 추천을 다시 계산하고 원하는 수량으로 수정·저장·확정합니다. CSV 또는 Excel을 받아 화면과 수량·매입액이 같은지 확인합니다.

다른 날 다시 테스트할 때에는 해당 날짜까지 판매 기록을 채우거나 새 테스트 매장을 만듭니다. 누락 날짜는 자동으로 0개로 채우지 않습니다. 실제 판매 0개는 정상 기록입니다.

## 내 자료로 시험

일반 매장을 추가하고 위치·상품을 등록한 다음 CSV/Excel 또는 직접 입력으로 최근 연속 56일의 판매를 저장합니다. 모델 설정에서 실시간 예보 TFT를 선택합니다. 현재 계약은 **기준일 마감 판매까지 56일 → 다음 날부터 7일**입니다.

실제 자료를 넣어도 모델 자체는 합성 학습 모델입니다. 이 기능은 일반 상품 ID와 실시간 예보가 추론·발주에 연결되는지를 직접 확인하는 용도입니다. 한국 점포의 예측 정확도나 절감액 검증은 별도입니다.

예측이 실패해도 판매·상품·재고 입력 화면은 유지됩니다. 모델 준비 중, 판매 기록 부족, 예보 누락·갱신 실패를 구분해 안내하며, TFT 실패를 요일 기준선으로 조용히 대체하지 않습니다. 과거 날짜는 과거 날씨 시나리오로 표시합니다. 56일만 생성한 합성 매장은 더 이른 기준일을 계산할 판매 이력이 부족할 수 있습니다.

## 데이터와 실행 경계

| 항목 | 이번 테스트 경로 |
| --- | --- |
| 매장·상품 ID | 사용자가 만든 일반 ID. Walmart ID로 바꾸지 않음 |
| 입력 판매 | 기준일 포함 연속 56일, 관측한 0개와 미입력 구분 |
| 미래 기상 | 실제 API의 일별 최고·최저 기온(°C), 강수량(mm), 다음 7일 |
| 시간대 | 매장에 저장된 IANA 시간대, 기존 한국 매장은 Asia/Seoul |
| 예보 기록 | 제공처·조회 시각·대상 날짜·사용값을 예측과 함께 저장. 조회 시각을 기상모델 발급 시각이라고 부르지 않음 |
| 모델 | 별도 합성 학습 TFT, 매장·상품 ID embedding 없음, CPU 실행 |
| 출력 | 상품마다 날짜·P10·P50·P90. 재고·원가·발주량은 API가 계산 |
| 학습/추론 | 학습 CLI와 서버 추론 분리. 웹 요청 중 재학습하지 않음 |

Open-Meteo의 날짜·단위·daily 변수는 [공식 Forecast API 문서](https://open-meteo.com/en/docs)를 따릅니다. 이 모델은 decoder에 미래 예보를 넣고 encoder에는 판매·달력 정보를 사용합니다. 원본 Walmart persistence 모델의 미래 기상 처리를 변경한 것이 아닙니다.

## 팀원에게 넘길 일

웹·API·배포 담당은 일반 매장 선택, 실제 예보 수집, 별도 추론 프로세스, 재고·발주와 다운로드, 직접 테스트 화면을 맡습니다.

Walmart 모델 담당의 우선 작업은 기존 체크포인트의 `provided_forecast` 경로를 검증하는 것입니다. 날짜를 옮긴 시연과 별도로, 원래 시간축의 분리된 검증 구간에서 persistence와 비교하고 분위수 손실·구간 포함률·영판매 오차를 기록합니다. 당시 발급된 예보를 확보하지 못했다면 관측·재분석 날씨를 넣은 결과임을 명시합니다. °C/mm/m/s → °F/inch/mph 변환, 저장된 정규화 설정, 미래 7일 입력 순서도 확인합니다. 새 평가와 가중치가 검증되기 전에는 기존 정확도 수치를 예보 입력 성능으로 표시하지 않습니다.

합성 자료 모델을 개선한다면 `ml/merchant_tft/`의 입력·출력 계약을 유지하면서 다음을 맡습니다.

1. 합성 학습 시나리오를 검토하고 상품 수요 수준·요일·기온·강수 조건을 다양하게 학습합니다. 가정으로 만든 효과와 관측 자료에서 확인한 효과를 구분합니다.
2. 학습과 분리한 합성 표본에서 기준선 비교·분위수 손실·구간 포함률·영판매 처리를 확인합니다. 동일 입력에서 예보만 바꿨을 때 결과가 달라지는지도 검증합니다. 이 수치는 합성 자료 평가로 표시합니다.
3. 개선 모델은 가중치·해시·설정·학습 명령·검증 결과·CPU 입출력 예제를 함께 PR로 전달합니다. 기존 Walmart 평가의 6.98%/10.71%를 새 모델에 붙이지 않습니다.
4. 새 모델의 검증이 끝나면 API·웹 담당이 같은 계약의 가중치로 교체하고 실제 예보→발주까지 다시 검증합니다. 기존 운영 모델을 학습 도중 자동 교체하지 않습니다.

실제 판매 성능 검증을 이어갈 때 필요한 발급 예보 기록과 시간 분할은 [실제 예보 모델 조건](../ml/forecast-support.md)에 정리돼 있습니다. 이번 해커톤 테스트를 시작하는 데 실제 점포 자료가 필수인 것은 아닙니다.
