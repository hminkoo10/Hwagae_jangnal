# 직원 관리 · 화면 분리

## 화면 분리

| 주소 | 대상 | 다른 계정이 로그인하면 |
| --- | --- | --- |
| `/` | 점주·직원 | 운영자: 세션을 저장하지 않고 관리자 페이지 링크를 안내 |
| `/admin` | 서비스 운영자 | 점주·직원: 세션을 저장하지 않고 매장 화면 링크를 안내 |
| Android·iPhone 앱 | 점주·직원 | 운영자: "웹 관리자 페이지에서 로그인" 안내, 링크 없음 |

- 두 화면은 같은 세션 저장소(`hwagae-session`)를 써서 기존 로그인은 그대로 이어집니다. 예전에 `/`에서 로그인한 운영자는 `/`에서 관리자 페이지 이동 링크를 봅니다.
- 앱 빌드(`npm run mobile:build`)는 `src/app/admin`을 빼고 만들어 앱에 운영자 화면이 들어가지 않습니다. `mobile:check`가 `www/admin`이 없는지 확인합니다.
- 점주 초대 링크(`/#invite=`)와 직원 초대 링크(`/#staff-invite=`)는 모두 `/`에서 열립니다.

## 직원 초대

점주 → **직원 관리** → 이름·이메일·할 수 있는 일 선택 → **초대하기**.

- 새 이메일: 초대 링크를 만들어 복사합니다. 이메일은 자동 발송하지 않습니다. 링크는 7일 유효·1회용이며 DB에는 토큰 해시만 저장합니다. **링크 다시 발급**은 이전 미사용 링크를 폐기합니다. 직원이 링크에서 12자 이상 비밀번호를 직접 정합니다.
- 이미 가입한 이메일(운영자 제외): 비밀번호를 바꾸지 않고 바로 매장 직원으로 추가합니다.
- 거부: 운영자 계정, 이미 이 매장에 소속된 계정(점주 포함), 소유하지 않은 매장으로의 초대. 다른 점주의 역할은 바꾸지 않으며 운영자 계정을 만들지 않습니다.

API: `GET/POST /stores/{id}/staff`, `PATCH /stores/{id}/staff/members/{user_id}`(권한·`status`), `POST …/members/{user_id}/remove`, `PATCH /stores/{id}/staff/invites/{invite_id}`(권한), `POST …/invites/{invite_id}/reissue`, `POST …/invites/{invite_id}/cancel`, `POST /auth/staff-invitations/inspect`, `POST /auth/staff-invitations/accept`. 관리 API는 해당 매장 점주만 쓸 수 있습니다.

## 권한

서버가 각 API에서 검사하고, 화면은 권한이 없는 버튼을 숨기거나 막습니다.

| 권한 | 기본 | 해당 API |
| --- | --- | --- |
| 판매 기록 입력 | 켜짐 | 판매 파일 확인·저장, 직접 입력 |
| 재고 확인 입력 | 켜짐 | 재고 저장 |
| 발주 계획 저장 | 켜짐 | 발주안 저장 |
| 발주 확정·내보내기 | 꺼짐 | 발주 확정, CSV·Excel 내보내기 |
| 상품 관리(추가·수정·제외) | 꺼짐 | 상품 등록·수정·발주 제외 |

매장 추가, 초기 자료 업로드, 예측 설정, AI 도우미, 직원 관리는 점주만 할 수 있습니다. 직원은 자기 권한을 바꿀 수 없습니다. 기존 직원은 업데이트 후 기본 권한(종전과 같은 범위)을 받습니다.

## 사용 중지 · 제외

- **사용 중지**: 그 매장에 들어올 수 없고 매장 목록에서 빠집니다. 다른 매장 소속이나 계약이 없으면 로그인 세션도 바로 끊습니다. **다시 사용**으로 되돌립니다.
- **매장에서 제외**: 소속을 지웁니다. 계정과 작성한 발주안은 남습니다. 같은 이메일로 다시 추가할 수 있습니다.
- 초대·추가·권한 변경·제외·가입은 감사 기록(`operator_audit`)에 남습니다.
