# 웹·API 구현 현황

기준일 2026-10-24. 웹·API의 점주 업무 흐름과 별도 TFT 과거 시연 경로를 구현했습니다.
이 문서는 현재 동작을 기록합니다. [기능 명세서](functional-spec.md)는 초기 요구·설계 제안이며,
인터뷰 18~34의 미답변 항목을 확정 답변으로 간주하지 않습니다.
[3분 시연 안내](demo-runbook.md)와 [배포 기록](deployment.md)은 따로 관리합니다.

## 사용할 수 있는 흐름

1. 점주·직원 로그인 → 소속 매장 전환.
2. 상품 등록·설정 → CSV·Excel 미리보기·저장 또는 직접 판매 입력.
3. 실제 날씨 확인 → 날씨를 사용하지 않는 요일 기준선의 상품별 7일 예측.
4. 만료일별 재고·입고 예정 직접 확인 → 추가 발주량 계산.
5. 수량 수정 → 초안 저장 → 점주 확정 → CSV·Excel 발주서.
6. 과거 기준일 선택 → 이후 기록을 가린 예측과 실제 판매 비교.
7. **TFT 모델 체험 · 직접 예측** → Walmart 표본 매장 선택 → 실제 TFT 실행 → 같은 56일 입력의 요일 기준선·이후 실제 판매와 비교.
8. **발주 준비** → 같은 표본의 개인 시연 재고·입고·가격·납기 저장 → TFT 발주 추천 → 수량 수정·초안 저장·수정 → 점주 확정·CSV/Excel 내보내기.
9. **모델 평가** → 전체 테스트 또는 56일 관측 충족 집합 선택 → TFT·평가 당시 API 기준선·날씨 제거 TFT의 저장된 평가표 조회.

## 자료와 모델을 구분하는 기준

일반 매장의 초기 자료는 2개 매장·각 10개 상품·84일의 가상 판매입니다. 재고는 직접 확인하기 전까지 비어 있습니다.
TFT 화면은 기준일 2014-09-12의 Walmart 공개 자료를 사용합니다. 매장 4·24·17에 각각 6·3·1개, 총 10개 상품이 있습니다.
각 상품의 연속 56일 판매로 다음 7일을 예측합니다. 이후 실제 판매 70행은 별도 파일에서 읽어 추론·출력 검사가 끝난 뒤 연결하며 모델 입력에는 넣지 않습니다.
별도 Python 3.11 프로세스가 학습된 모델을 실행하며, 예상 출력 파일을 실행 결과로 표시하지 않습니다.
이 시연은 일반 매장의 판매·재고·예측·발주 테이블에 쓰지 않습니다. 개인 시연 전용 테이블에 서버 예측·상품 설정·재고·추천·주문을 저장합니다.
발주 계산에는 비교 정답을 제외한 TFT 예측만 사용합니다. 2014-09-12 마감 재고와 이후 입고분을 반영하며, 가격·원가·납기·판매 가능 기간은 사용자가 확인하는 시연 가정입니다.
설정·예측 변경은 이전 초안을 만료시키고 동시 수정은 revision/version 충돌로 차단합니다. 확정본은 저장 당시 수량·원가로 내보내며 외부 공급사 주문은 전송하지 않습니다.

TFT는 마지막 관측 날씨가 7일간 이어진다는 `persistence`를 사용합니다. 실제 발급 예보를 입력하는 기능이 아닙니다.
직접 예측의 7일 표본 그래프와 **모델 평가**의 전체 테스트 성능을 구분합니다. 그래프에서 예측선이 더 높다는 사실만으로 성능이 좋다고 판단하지 않습니다.
평가 탭은 같은 매장·상품·기준일·예측일의 저장된 결과를 비교하며, 화면을 열 때 전체 테스트를 다시 추론하거나 학습하지 않습니다.

| 평가 집합 | 상품·일 행 / 예측 창 | TFT MAE | 평가 당시 API 기준선 MAE | 기준선 대비 MAE 감소 |
| --- | ---: | ---: | ---: | ---: |
| 원본 테스트 전체 | 7,973 / 1,139 | 5.5221 | 5.9363 | 6.98% |
| 최근 56일 모두 관측 | 1,701 / 243 | 5.2486 | 5.8780 | 10.71% |

위 평가는 TFT 56일·API 기준선 최대 84일 입력을 사용합니다. 직접 예측 화면의 기준선은 같은 표본의 56일만 사용합니다.
단일 seed 실험이며 날씨 포함·제거 모델의 학습 환경도 달라, 차이를 날씨의 순수한 인과 효과로 단정하지 않습니다.
품절로 놓친 실제 수요, 한국 점포 적용 성능, 실시간 예보의 추가 효과, 폐기·이익 개선은 검증하지 않았습니다.
수치의 출처는 [평가표](../ml/evaluation/api-comparison/metrics.csv), 조건은 [ML 평가 기록](../ml/evaluation.md)을 따릅니다.
검산용 [평가 자료 ZIP](../ml/evaluation/tft-evaluation-data.zip)의 입력 해시 확인과 6행 지표 재계산을 통과했습니다. 실제 검증 범위는 [시연 안내의 검증 기록](demo-runbook.md)을 따릅니다.

## 현재 정책과 한계

| 항목 | 구현 |
| --- | --- |
| DB | sqlite3. 기본 data/runtime/hwagae.sqlite3, 외부 DB 계정 불필요 |
| 체험 자료 | 2매장·각 10상품·84일 가상 판매. 공개·실제 점포 자료가 아님 |
| 재고 | 최초 미입력. 직접 확인한 0과 구분, 오늘 마감 기준 재확인 |
| 역할 | 점주: 관리·확정·내보내기. 직원: 소속 매장 조회·판매/재고 입력·초안 |
| 계정 | 초기 체험 계정. 가입·초대·비밀번호 변경 UI 미구현 |
| 입력 | CSV·XLSX 첫 시트·직접 입력. 미리보기 후 저장, 중복은 전체 취소 |
| 납기 | 상품별 1~30일, 발주 주기 1~7일. 당일 납기·마감·묶음 주문 미지원 |
| 만료 | 배치별 수량·만료일, 만료일 마감까지 판매, 먼저 만료되는 재고부터 소비 |
| 날씨 | Open-Meteo 실시간 예보·과거 재분석, 30분 캐시. 당시 발급 예보 보관 미구현 |
| 일반 매장 예측 | 요일별 경험적 P10·P50·P90, 요일마다 4개 이상 관측 필요. **날씨 미반영** |
| TFT 과거 시연 | 3매장·10상품 선택, 56일 입력 → 7일 P10·P50·P90. 추론 후 실제 판매 연결, 같은 56일 기준선과 비교. 개인 시연 재고·입고 기반 추천/저장/확정/내보내기 |
| 모델 평가 | 전체 7,973행·56일 관측 충족 1,701행의 세 모델 평가표. MAE·WAPE·분위수 손실·구간 포함률, 입력 일수·단일 seed·환경 차이 표시 |
| 모델 실행 | API Python 3.14와 모델 Python 3.11 분리. 준비 전·장애·동시 요청·시간 초과 안내. 일반 매장 provider는 현재 TFT로 교체하지 않음 |
| 발주 | 납기+주기-1일 범위에서 고정 수요 3경로를 균등 비교하는 근사 계획 |
| 비용 | 폐기×원가 + 미충족수요×(판매가-원가), 추가 처리·보관비·회수액 0, 유효 말기 재고 원가 이월 |
| 상태 추적 | 자료 변경 후 이전 계산으로 저장·확정 불가. 확정 파일은 당시 값 유지 |
| 배포 | Ubuntu systemd·Nginx·GitHub Actions. API·웹·ML 전처리·샘플·평가 계산 검사, 모델 파일이 있으면 실제 추론과 전체 ML 테스트 후 활성화 |
| 후속 | 한국 점포·실제 예보·여러 seed 검증, 가입/초대·AI 입력·PDF·POS·공급사 자동 주문 |

시나리오 비중은 검증한 확률이 아니며, 일별 분위수를 기간 분위수로 합산하지 않습니다.
비용 최적·실제 수익 증가를 보장하지 않습니다. 7일 범위 초과는 계산을 보류합니다.
현재 재고를 과거 주문 계산에 사용하지 않습니다. 과거 날씨는 재분석이며 당시 예보가 아닙니다.
