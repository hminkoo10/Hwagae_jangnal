# 화개장날 3분 시연 안내

실제 TFT 추론에서 재고·입고 반영 발주서까지 한 흐름으로 보여줍니다.
현재 동작은 [구현 현황](implementation.md)을 기준으로 하며, [기능 명세서](functional-spec.md)는 초기 요구·설계 기록입니다.

## 바로 시작하는 실시간 예보 시연

점주 로그인 → **실시간 TFT 테스트 매장 만들기** → 지역 선택 → **7일 판매 예측** → **재고 확인** → **발주 계획** 순서로 진행합니다. 상품 5개와 오늘을 포함한 56일의 가상 판매·재고·입고가 자동으로 준비됩니다. 지역의 실제 예보를 별도 합성 학습 TFT에 입력합니다. 자세한 조작과 팀원 할 일은 [실시간 예보 직접 테스트](live-weather-test.md)를 참고하세요.

## 시연 경로

| --- | --- | --- |

실시간 날씨가 보인다는 사실이 일반 매장의 예측에 날씨가 반영된다는 뜻은 아닙니다.
Walmart TFT의 미래 날씨는 마지막 관측값을 7일 유지하는 `persistence`입니다. 당시 발급 예보를 사용한 예측은 아닙니다. 실시간 테스트 모델의 합성 학습 결과와 Walmart의 실제 판매 평가를 구분합니다.
Walmart TFT 시연 결과는 로그인 계정별 개인 공간에 저장합니다. 일반 매장의 판매·재고·발주 테이블과 분리됩니다.
직접 예측의 실제 판매값은 추론 후에만 연결합니다. 모델 평가의 기준선은 최대 84일을 사용하므로 직접 예측의 56일 기준선과 구분합니다.

## Walmart 과거 평가 시연 준비

1. 점주 계정으로 로그인합니다. 로컬 기본 샘플은 **점주 체험** 버튼을 사용할 수 있습니다. 운영 로그인 정보는 배포 담당자가 별도로 관리합니다.
2. TFT 시연에서 사용할 매장·상품 하나를 정합니다. 예: Walmart 매장 4의 item 9. 실제 상품 종류·가격을 추측하지 않고 원래 표본 이름을 유지합니다.
3. 선택 상품의 판매가가 원가보다 높고 `납기 + 발주 주기 - 1 ≤ 7`인지 확인합니다. 재고 미입력과 직접 확인한 0개의 차이를 보여줄 수 있도록 준비합니다.
4. TFT 시연은 **2014-09-12 마감** 기준입니다. 예: 현재 재고 20개(만료 9월 15일), 9월 13일 입고 10개(만료 9월 16일). 가격·원가·납기는 시연 가정임을 설명합니다. 일반 매장 재고 화면을 사용할 때만 오늘 날짜를 사용합니다.
5. **TFT 모델 체험 → 직접 예측**에서 **상태 다시 확인**을 눌러 준비 완료인지 확인합니다. 매장 선택지 3개와 상품 수 6·3·1개, 선택 매장의 실제 예측·실제 판매 표시를 확인합니다. **모델 평가**에서 전체/56일 관측 충족 집합 전환도 확인합니다. 설정은 [모델 규약](model-contract.md)을 따릅니다. `/health` 성공만으로 TFT 준비 완료를 판단하지 않습니다.
6. 다운로드 저장 위치와 화면 크기를 확인합니다. 리허설은 승인된 시연 매장 또는 별도 로컬 DB에서 진행하며 운영 DB를 지워 초기화하지 않습니다.

초기 샘플은 DB를 처음 만들 때 생성됩니다. 리허설에서 저장한 판매·재고·발주가 다음 실행에도 남을 수 있으므로 같은 CSV를 반복 저장하지 않습니다.
일반 매장의 `FORECAST_PROVIDER`는 비워 두고, 별도 TFT 환경만 설정합니다.

수량·매입액은 화면의 실제 계산값을 읽습니다. 특정 추천 개수나 응답시간을 미리 보장하지 않습니다.
재고·상품 설정을 바꾸거나 TFT를 새로 실행한 뒤에는 다시 계산한 발주안으로 저장·확정합니다. 개인 시연의 저장본은 본인 계정에 남습니다.

## 질문받았을 때 설명할 범위

- **날씨 덕분에 정확도가 좋아졌나?** 날씨 포함·제거 TFT와 API 기준선의 같은 평가 행 비교를 제공합니다. 다만 단일 seed이며 두 TFT의 학습 환경도 달라 날씨만의 인과 효과로 단정할 수 없습니다. 미래 날씨는 persistence이고 실제 발급 예보를 사용하지 않았습니다.
- **차트에서 TFT가 기준선보다 높으면 더 좋은가?** 예측값이 다르다는 뜻입니다. 이후 실제 판매와 얼마나 차이 나는지 확인해야 합니다. 직접 예측의 7일 표본을 전체 성능으로 일반화하지 않고 **모델 평가**의 집계와 조건을 함께 봅니다. 범위는 [ML 평가 기록](../ml/evaluation.md)을 따릅니다.
- **P10~P90이면 정확도 80%인가?** 모델의 분위수 범위입니다. 평가 탭에는 실제 구간 포함률을 별도로 표시하며, 명목 범위를 정확도나 보장으로 설명하지 않습니다.
- **실제 수요·폐기·이익 개선을 증명했나?** 관측 판매량이 품절로 놓친 수요 전체를 나타내지는 않습니다. 실제 한국 점포 수요와 폐기·이익 개선은 아직 검증하지 않았습니다.
- **발주량이 최적인가?** 현재는 고정 수요 3경로의 비용 비교를 이용한 근사 계획입니다. 실제 재고·납기·만료·원가 가정에 따라 결과가 달라집니다.

## 실패 시 복구

| 증상 | 대응 |
| --- | --- |
| 로그인 만료·권한 오류 | 다시 로그인하고 점주 계정인지 확인합니다. 직원은 최종 확정·내보내기를 할 수 없습니다. |
| CSV 중복·형식 오류 | 오류 행을 확인합니다. 기존 값을 덮어쓰지 않고 저장하지 않은 준비 행으로 교체합니다. 미리보기만으로는 DB에 저장되지 않습니다. |
| 재고 미입력·오래된 재고 | 오늘 수량·만료일·입고 예정을 확인하고 저장한 뒤 다시 계산합니다. 재고 없음은 직접 확인한 0개로 입력합니다. |
| 계산 기준 변경 안내 | 최신 판매·상품·재고로 다시 계산하고 새 초안을 저장합니다. 이전 계산을 억지로 확정하지 않습니다. |
| 날씨 조회 실패·오래된 캐시 | 화면의 상태·시각을 그대로 설명합니다. 날씨를 사용하지 않는 일반 매장 기준선의 업무 흐름을 계속 시연할 수 있습니다. |
| TFT 준비 중 | 잠시 후 **상태 다시 확인**을 누릅니다. 준비 전 반복 실행하지 않습니다. |
| TFT 환경 없음 | 배포 담당자가 모델 Python·체크포인트 설정을 확인합니다. 변경 후 API를 다시 시작하고 준비 상태를 확인합니다. |
| TFT 연결 실패·시간 초과 | API 로그와 모델 환경을 확인하고 API를 다시 시작합니다. 복구가 늦으면 점주 업무 흐름으로 시연을 마무리하고 모델 실행 장애를 설명합니다. |
| 평가 자료 조회 실패 | 평가 화면의 재시도 버튼을 사용합니다. 계속 실패하면 평가 파일·서버 로그를 확인하며, 실패한 응답을 추정 수치로 대체하지 않습니다. |
| API 연결 자체가 안 됨 | 웹·API 프로세스, 주소와 포트, 로컬 CORS 설정을 확인합니다. 운영에서는 배포 담당자가 서비스 상태를 확인합니다. |

저장된 예상 JSON, 스크린샷이나 기준선을 현재 TFT가 실행한 결과로 표시하지 않습니다.
복구용 서버 절차와 배포 되돌리기는 [배포 안내](deployment.md)를 따릅니다.
