# 화개장날 요구사항 인터뷰 기록

- 기준일: 2026-10-24, Asia/Seoul
- 상태: 1차 1~16 답변 완료, 2차 17 답변 완료, 18~34 답변 대기
- 연결 문서: [기능 명세서](functional-spec.md)

답변은 사용자의 요구이며, 아래 ‘제안’은 아직 채택되지 않은 구현안입니다.
사용자가 일부만 답한 경우 나머지 질문의 첫 번째 선택지를 승인한 것으로 간주하지 않습니다.

## 1. 확정한 요구

| 질문 | 사용자 답변 요지 | 반영 |
| --- | --- | --- |
| 01 첫 업종 | 완제품을 받아 파는 식품 매장, 상품별 발주 개수 | 원재료·레시피 환산 범위 제외 |
| 02 첫 사용자 | 심사위원이 샘플 매장으로 체험 | 체험 중심의 화면·시연 경로 |
| 03 자료 확보 | 공개 데이터만 있음 | 실제 점포 자료·재고·성과로 표현하지 않음 |
| 04 규모 | 여러 매장, 각각 10~50개 상품 | 매장별 자료와 접근 분리, 시연 개수는 추가 질문 |
| 05 줄일 손실 | 폐기·품절을 적정선에 맞춤 | 두 손실의 균형을 비교. 구체적인 비용 정책은 설계안 |
| 06 판매 입력 | CSV·Excel·직접 입력 모두, 가능하면 글을 AI로 가져오기 | 세 방식 필수, AI 입력 방식은 추가 질문 |
| 07 재고 | 자료 확보가 어려움 | 미확인과 0개를 구분 |
| 08 납기 | 회사마다 다름 | 단일 고정 납기 사용 금지, 설정 방식 추가 질문 |
| 09 판매 가능 기간 | 상품마다 다름 | 재고 이월·만료 처리 필요, 상세 방식 추가 질문 |
| 10 예측 기간 | 앞으로 7일 | 다음 날부터 7일인지는 기준 시각과 함께 설계 제안 |
| 11 비용 입력 | 판매가와 매입/준비 원가만 | 완제품 매장에서는 판매가·개당 매입 원가로 표현 |
| 12 모델 | 더 괜찮은 방법으로 선택 위임 | 요일 기준선·LightGBM부터 비교, TFT는 검증 후 선택 |
| 13 날씨 | 실시간 예보와 과거 재생 모두 | 현재 예보·당시 예보·관측 날씨 구분 |
| 14 계정 | 점주·직원, 여러 매장 관리 필요 | 역할·매장 접근 기능 필수. 가입·초대 깊이는 미정 |
| 15 추천 후 작업 | 수정·저장·발주서 파일 내보내기 | 기능 필수, 파일 형식·확정 권한 추가 질문 |
| 16 대회·일정·디자인 | 디미고 스타트업 해커톤, 3일 뒤, 배점 모름, AI 적극 활용, PWA 설치 제외, 배민 사장님처럼 보기 쉽고 세련되게 | 마감 추정 2026-10-27. 시간·역량·이름은 추가 질문 |
| 17 재고 없을 때 | **재고를 직접 입력하기 전에는 수요 예측만 표시** | 재고를 0으로 가정하지 않음. 상품별 발주량·매입액 미계산 상태 표시 |

17번에서 합성 재고를 자동으로 채워 발주량을 보여주는 안은 선택되지 않았습니다.
체험 자료의 재고는 사용자가 직접 입력하기 전까지 비어 있어야 합니다.

## 2. 이미 보낸 2차 질문 — 답변 대기

아래 질문은 대화에서 이미 전달했습니다. 중복으로 다시 답할 필요는 없습니다.
제안란은 비교를 돕기 위한 추천안이며 확정 요구가 아닙니다.

## 3. 2차 답변 후 필요한 세부 확인

한 번에 모두 확정하지 않고, 선택한 방식에 해당하는 질문만 이어갑니다.

- 판매 입력: 날짜 형식, 중복 시 교체·합산, 반품·취소, 휴무와 누락일, 허용 파일·행 수.
- 재고: 입력 시각, 오래된 재고의 재확인, 만료일의 판매 가능 마지막 시각, 입고 예정이 없다는 확인.
- 주문: 발주 기준 시각, 당일 납기 지원, 묶음·최소 주문, 직원 권한과 수정 충돌.
- 모델: 선정 데이터셋 원본, 최소 이력, 신규 상품·매장의 대체 처리, 예측 분위수와 기간 경계.
- 체험: 수동 입력 값의 초기화, 여러 심사위원의 자료 분리, 저장·삭제 범위, 인터넷 실패 시 시연 방법.

- 2026-10-24: 17번 답변 반영. 재고 직접 입력 전에는 수요 예측만 표시하도록 확정.
