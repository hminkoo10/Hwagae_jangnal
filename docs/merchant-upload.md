# 점주가 직접 자료를 가져오는 흐름

1. 매장 선택 옆 **+** → 매장명과 지역을 선택해 빈 매장을 등록합니다. 예: **화개마켓 댈러스점 / 댈러스, 텍사스**.
2. **우리 매장 자료를 가져오세요**에서 준비한 XLSX를 선택합니다.
3. **내용 확인하기**에서 상품 수·판매 기간·재고 기준일·상품별 가격을 확인합니다. 이 단계에서는 DB에 저장하지 않습니다.
4. 현재 재고와 입고 예정 목록 확인에 체크하고 **확인한 자료 저장**을 누릅니다. 상품·판매·재고는 한 번에 저장되며 오류가 있으면 전체를 취소합니다.
5. 홈 → 7일 판매 예측 → 재고 확인 → 발주 계획 순서로 사용합니다. 미래 날짜는 **발주 예정일**에서 고릅니다.
6. 발주 수량 수정 → 저장 → 점주 확정 → CSV/Excel 내보내기.

## 업로드 파일

필수 시트와 첫 행:

- `상품`: id, name, category, supplier, price, cost, lead_days, shelf_days, review_days
- `판매`: date, product_id, units_sold
- `재고`: product_id, measured_on, quantity, expires_on, arrives_on

날짜는 YYYY-MM-DD, 수량·가격은 정수입니다. `arrives_on`을 비우면 현재 재고, 채우면 입고 예정입니다. 모든 상품은 매장 **현지 오늘** 기준 재고를 명시해야 합니다. 실제 0개도 0으로 적습니다. 입고 예정은 내일부터, 만료일은 입고일 이후여야 합니다. 업로드 후 현재 재고가 바뀌면 재고 확인 메뉴에서 다시 저장합니다.

초기 자료는 **상품이 없는 매장**에만 가져옵니다. 매장당 상품 1~50개, 시트당 10,000행, 파일 5MB, 압축 해제 30MB 제한입니다. 수식은 실행하지 않고 거부합니다. 이미 등록한 매장의 일별 판매는 기존 CSV/XLSX 판매 업로드를 사용합니다. 같은 날짜·상품은 자동 덮어쓰지 않습니다.

## 제공 자료 재생성

```powershell
uv run python scripts/make-merchant-data.py --output C:\원하는\폴더
```

현재 댈러스 날짜를 기준으로 상품 6개와 공개 판매 112일(672건), 재고·입고 목록을 생성합니다. 날짜를 고정하려면 `--as-of 2026-10-24`를 추가합니다. 다른 날 시연할 때에는 파일을 다시 생성하고 새 매장에 가져옵니다.

판매 수량은 Walmart Stormy Weather 공개 기록의 날짜를 옮깁니다. 상품명·분류·공급사·가격(원)·재고는 가정값이며 원본 Walmart 상품명을 식별한 것이 아닙니다. 선택한 날씨 위치와 원본 매장의 좌표도 일치한다고 주장하지 않습니다. 출처와 가정은 파일 안내 및 접힌 **예측 설정·데이터 안내**에서 확인합니다.

제공 파일의 `모델연결` 시트는 기존 Walmart 체크포인트의 학습 상품·원본 판매 전체가 맞는지 검증하기 위한 프로필입니다. 서버가 상품 코드·112일 판매·날짜를 검증한 뒤에만 저장된 상품 embedding과 원본 과거 날씨를 연결합니다. 임의의 상품을 Walmart 상품으로 바꾸지 않습니다. 해당 시트 없는 일반 파일은 별도의 일반 매장 TFT를 사용하며, 이 모델은 합성 자료 학습임을 설정에서 명시합니다.

예보 입력 경로의 성능은 별도 검증 전입니다. 기존 persistence 평가 지표를 새 예보 예측 성능으로 표시하지 않습니다. 일반 운영 화면은 판매·재고·발주 작업 중심이며, 공개 데이터 체험용 메뉴와 자동 자료 생성 버튼을 노출하지 않습니다.
